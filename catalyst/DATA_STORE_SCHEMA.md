## How the mapping works

Catalyst Data Store is relational, so the ER diagram maps ~1:1.

- **Primary keys** — every Data Store table has an automatic `ROWID` PK. Keep the
  schema's own IDs (`CaseMasterID`, `DistrictID`, …) as **Number** columns so the
  business keys and foreign keys still line up. Seed them explicitly.
- **Foreign keys → Lookup columns.** A `Lookup` column references another table
  and *is* the FK. It enforces the relationship and enables JOINs in **ZCQL**
  (Catalyst's SQL). Where you prefer to seed by CSV first and wire relationships
  later, use a plain **Number** column and convert it to a Lookup afterwards.
- **Queries** use ZCQL from a Function, e.g.
  `SELECT CaseMaster.CrimeNo, District.DistrictName FROM CaseMaster
   LEFT JOIN Unit ON CaseMaster.PoliceStationID = Unit.UnitID
   LEFT JOIN District ON Unit.DistrictID = District.DistrictID`.

### Type mapping
| ER diagram type | Catalyst column type |
|---|---|
| `INT` (PK/FK/plain) | Number (Lookup for FKs) |
| `VARCHAR`, `CHAR`, `NVARCHAR(MAX)` | Text |
| `DATE` | Date |
| `DATETIME` | DateTime |
| `BIT` | Boolean |
| `DECIMAL` (lat/long) | Decimal |

### Import order (parents before children — Lookups need the target rows to exist)
1. **Masters/geo:** `State` → `District` → `UnitType` → `Unit` → `Rank` →
   `Designation` → `Employee` → `Court`
2. **Lookups:** `CaseCategory`, `GravityOffence`, `CaseStatusMaster`,
   `CasteMaster`, `ReligionMaster`, `OccupationMaster`
3. **Crime classification:** `CrimeHead` → `CrimeSubHead`; `Act` → `Section`;
   `CrimeHeadActSection`
4. **Core transactional:** `CaseMaster` → `ComplainantDetails`, `Victim`,
   `Accused`, `ActSectionAssociation`, `ArrestSurrender`, `ChargesheetDetails`,
   `Inv_OccuranceTime`, `inv_arrestsurrenderaccused`

## Fastest way to create the tables
Use Data Store's **CSV import** — importing a CSV auto-creates the table with
columns inferred from the header, then bulk-loads the rows. Seed CSVs for the
backbone tables are in [`catalyst/seed/`](./seed) (generated by
[`gen_seed.py`](./gen_seed.py)). Import them in the order above, then convert the
`*ID` FK columns to **Lookup** columns pointing at their parent table.

## Extended tables — not yet built

6 more tables the ER diagram defines beyond the 21-table backbone above.
Not required by the current UI, so deferred — but if/when they're needed
(arrest tracking or complainant demographic detail), build these exact
columns rather than re-deriving from `Police_FIR_ER_Diagram.pdf`:

**ArrestSurrender** — `ArrestSurrenderID`(Num,PK) · `CaseMasterID`(Lookup→CaseMaster)
· `ArrestSurrenderTypeID`(Num — arrest vs voluntary surrender, lookup value)
· `ArrestSurrenderDate`(Date) · `ArrestSurrenderStateId`(Lookup→State)
· `ArrestSurrenderDistrictId`(Lookup→District) · `PoliceStationID`(Lookup→Unit)
· `IOID`(Lookup→Employee — investigating officer) · `CourtID`(Lookup→Court)
· `AccusedMasterID`(Lookup→Accused) · `IsAccused`(Bool) ·
`IsComplainantAccused`(Bool)

**inv_arrestsurrenderaccused** — junction table, one `ArrestSurrender` event
↔ multiple `Accused` (many-to-many). Minimum: `ArrestSurrenderID`(Lookup→ArrestSurrender)
· `AccusedMasterID`(Lookup→Accused).

**CrimeHeadActSection** — `CrimeHeadID`(Lookup→CrimeHead) · `ActCode`(Lookup→Act)
· `SectionCode`(Text) — maps a major crime head to its applicable act-sections.

**CasteMaster** — `caste_master_id`(Num,PK) · `caste_master_name`(Text).
Referenced by `ComplainantDetails.CasteID` (currently a plain Number column
with no lookup target — wire it up when this table exists).

**ReligionMaster** — `ReligionID`(Num,PK) · `ReligionName`(Text). Referenced
by `ComplainantDetails.ReligionID` (same caveat as above).

**OccupationMaster** — `OccupationID`(Num,PK) · `OccupationName`(Text).
Referenced by `ComplainantDetails.OccupationID` (same caveat as above).

## How the current UI maps onto these tables
| UI element | Source |
|---|---|
| Districts (Bengaluru Urban, Mysuru…) | `District` |
| Case types (Theft, Assault, Fraud, Burglary) | `CrimeSubHead` (under `CrimeHead`) |
| Case files (FIR-1001…) | `CaseMaster` (+ `Victim`/`Accused`/`ComplainantDetails`) |
| District clearance rate | `COUNT(CaseStatusID IN chargesheeted/closed) / COUNT(*)` per district |
| Year trend sparkline | `COUNT(*)` grouped by `YEAR(CrimeRegisteredDate)` + district |
| Sections invoked (379 IPC…) | `ActSectionAssociation` → `Section` |

The investigation-board evidence/graph/AI data has **no** table in this FIR
schema — keep it in **Catalyst NoSQL** (document-shaped) or as mock.

## CrimeNo format (per the ER diagram)
`1 digit Case Category + 4 digit District + 4 digit Unit + 4 digit Year + 5 digit serial`
e.g. FIR `1 4401 0006 2026 00001` → `144010006202600001`. `CaseNo` = `YYYY` + 5-digit serial (the last 9 digits).
